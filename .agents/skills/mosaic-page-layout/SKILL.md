# Mosaic page layout

Use existing Mosaic screens as visual references while keeping each feature's content and workflow specific.

## Source of truth

- Read the target feature's page and nearby components before styling.
- Follow shared colors, typography, controls, and spacing already used by the app.
- Prefer existing shared components when available.

## Page patterns

- Use a centered `max-w-[1440px]` content area with `space-y-5 pb-8` when the screen layout supports it.
- Use a compact header with a small uppercase eyebrow, title, optional subtitle, and actions aligned right.
- For multi-step feature flows, make the landing page explain the choices before opening a workspace.
- Use real tables for data that benefits from row and column comparison; keep headers, borders, and typography readable.
- Carry the app palette forward: navy `#003366`, blue `#31577D`, gold `#C9A84C`, white surfaces, and slate borders. Keep geometry square and avoid decorative elements that do not improve hierarchy or use.

## Applying the pattern

Inspect the target feature before editing. Keep labels, data, permissions, and behavior owned by that feature; this skill supplies layout guidance, not product copy or behavior.
